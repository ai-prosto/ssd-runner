# Чек-лист приёма изменений в репозитории инструмента

Регламент для BEH-38 (NFR-11, AC-25). Ручная проверка: автоматического гейта нет
(CI-проверка ждёт ответа на Q-05). Применяется ревьюером к каждому изменению,
которое предлагается в основную ветку.

## Когда применять

Изменение кода инструмента: новая функция или исправление дефекта. Правки только
документации и данных прогонов чек-листу не подлежат, и ревьюер указывает это в записи.

## Проверки

Отметьте каждый пункт. Если не выполнен хотя бы один, изменение отклоняется.

- [ ] **Тест на новую функцию.** Для новой функции в самом изменении есть сопровождающий
      тест, который проверяет поведение, а не наличие файла и не метрику покрытия.
- [ ] **Тест на дефект.** Для исправления дефекта в изменении есть регрессионный тест.
      В истории изменения (сообщение коммита или описание) записано, что тест падал
      до исправления и проходит после. Лучше отдельным коммитом с тестом перед
      исправлением, чтобы падение можно было воспроизвести.
- [ ] **Инструментарий зелёный** (BEH-37). На ветке изменения проходят:
      `uv run ruff check .`, `uv run pyrefly check`, `uv run pytest`.
      В записи приведены результаты запуска.

## Порядок работы ревьюера

1. Откройте разность изменения и определите вид: новая функция или дефект.
2. Пройдите проверки выше. Для дефекта найдите в истории запись о падении теста
   до исправления. Если сомневаетесь, откатите исправление и запустите тест.
3. Запустите три команды инструментария и сверьте с записью автора.
4. Примите решение и зафиксируйте его по правилам ниже.

## Отклонение

Изменение без сопровождающего теста в основную ветку не принимается. Отклонение
должно быть видно в истории ветки, а не только в обсуждении:

- пустой коммит на ветке изменения:
  `git commit --allow-empty -m "review: отклонено — нет теста на <функцию/дефект>"`;
- либо комментарий, который остаётся в истории ветки (описание слияния или запись
  в журнале ревью).

После добавления теста ревью проводится заново с начала чек-листа.

## Форма записи о ревью

```
Изменение: <коммит или ветка>
Вид: новая функция | дефект
Тест на функцию / регрессионный тест: <путь::имя> — есть | нет
Падал до исправления (только для дефекта): <ссылка на коммит или запись> — да | нет
ruff / pyrefly / pytest: зелёные | красные (<что именно>)
Решение: принято | отклонено
Ревьюер / дата:
```
