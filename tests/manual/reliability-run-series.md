# Журнал серии прогонов надёжности

Регламент и журнал для BEH-39 (NFR-01, AC-26). Ручной регламент: серия не
запускается автотестом, потому что десять живых прогонов дают флаки и расход
подписки, а не измерение.

## Действующий порог

**Не менее 9 из 10** прогонов завершены успешно (формулировка NFR-01).
Q-02 остаётся открытым: целевое значение для приёмки может стать 10 из 10 либо
8 из 10 после замера базовой линии. До ответа на Q-02 в журнал записывается
это значение. Пересмотр порога меняет только эту строку и поле «Порог» в записи серии.

## Единый регламент серии

1. **Размер серии:** 10 прогонов.
2. **Входные описания:** эталонное описание `tests/data/reference_input.md`.
   Для каждого прогона укажите, какое именно описание подано.
   Если серия идёт на нескольких описаниях, перечислите их все и распределение
   по прогонам.
3. **Запуск:** `uv run sprc-runner` с настройками из `sprc-runner.toml`.
   Каждый прогон запускается в чистом целевом каталоге.
4. **Модели этапов:** перед серией и в каждой строке журнала записываются модели
   четырёх этапов: `model_prepare`, `model_tasks`, `model_implement`, `model_review`.
   Берите их из настроек, действовавших в прогоне. Если настройки менялись
   посреди серии, это новая серия.
5. **Исход прогона:** `успех` — прогон дошёл до конца, и тесты целевого проекта
   проходят (код возврата прогона 0). Любой другой исход — `сбой`, с кратким
   указанием этапа и причины.
6. **Нельзя** пропускать неудачные прогоны, повторять их в зачёт или подменять
   серию меньшим числом прогонов. Недовыполненная серия не считается результатом.
7. **Результат серии:** доля успешных = успехи / 10. Серия соответствует порогу,
   если успехов не меньше порога.

## Записи серий

Каждая серия добавляется ниже отдельным разделом по шаблону. Запись не правится
после фиксации: новое измерение — новая серия.

### Шаблон

```
### Серия N — <дата>

Порог: <действующий порог> (Q-02: <открыт | решён>)
Версия инструмента: <коммит>
Модели этапов: prepare=<...>, tasks=<...>, implement=<...>, review=<...>

| # | Входное описание | Модели этапов (если отличаются) | Исход | Примечание (этап, причина сбоя) |
|---|------------------|---------------------------------|-------|---------------------------------|
| 1 |                  |                                 |       |                                 |
| … |                  |                                 |       |                                 |
| 10|                  |                                 |       |                                 |

Успешных: <k> из 10. Доля: <k/10>.
Соответствует порогу: да | нет.
```

### Записанные серии

Серий пока нет: измерение не проводилось. Доля успешных прогонов не определена,
и о соответствии порогу судить нельзя. Первая серия добавляется сюда по шаблону
после выполнения десяти прогонов.

### Блокеры серии

- **2026-11-14.** Серия не проводилась, ни один прогон не запускался — записи 0/10
  нет и быть не должно: это блокер, а не измерение. Причина: консольная команда
  `sprc-runner run` выполняет только подготовку — порты цикла задач в CLI
  не собираются, порт ревьюера не реализован, поэтому успех по пункту 5 регламента
  (тесты целевого проекта проходят) недостижим у любого прогона. Снятие блокера —
  задача DT-20 декомпозиции; затем проверка подключения цикла без платных вызовов,
  один живой сквозной прогон и только после его подтверждения — серия.
