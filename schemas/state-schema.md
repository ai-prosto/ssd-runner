# Схема состояния `state.json`

**Версия схемы: 1.0.** Один JSON-документ в каталоге прогона, перезаписываемый целиком
атомарно (временный файл рядом, fsync, переименование). Состояние отвечает на вопрос
«что делать дальше»; журнал `log.jsonl` — «что происходило» и при возобновлении не
читается. Читатель — `sprc_runner.core.state.decode_state`.

## Поля

| Поле | Тип | Описание |
|---|---|---|
| `schema_version` | строка | версия схемы, `МАЖОР.МИНОР` |
| `run_id` | строка | идентификатор прогона |
| `input_sha256` | строка | отпечаток входного описания (`input.md`) |
| `config` | объект | снимок применённой конфигурации |
| `stages[]` | массив | `name`, `status` (`pending\|done\|failed`), `model` (или `null`) |
| `tasks[]` | массив | `task_id`, `status`, `attempts`, `last_attempt`, `commit` |
| `cursor` | объект или `null` | `task_id` задачи в работе и `attempt` идущей попытки (или `null`) |
| `finished` | булево | прогон дошёл до конца |
| `reason` | строка или `null` | код причины: исход прогона (`all_succeeded`, `partial`) либо причина паузы (`interrupted`, `implement_subscription_limit`, `<этап>_<исход>`) |

`tasks[].status` — закрытый набор `pending | in_progress | done | failed`.
`tasks[].last_attempt` — `number`, `success`, `error_code` (или `null`);
`attempts` — число сделанных попыток (отказ инфраструктуры не считается).

## Засечки

Состояние пишется при старте прогона, завершении этапа, взятии задачи в работу,
старте попытки, завершении попытки, завершении задачи и постановке на паузу.
Внутришаговых засечек нет: прерванная попытка при возобновлении идёт заново.
После Ctrl-C задача, чей `status` — `in_progress`, и есть прерванная; `cursor`
указывает на неё и на номер попытки.

## Версионирование

Добавление поля — минорное расширение. Смена смысла или удаление поля — новая
мажорная версия; читатель отвергает чужой мажор с `StateFormatError`.
